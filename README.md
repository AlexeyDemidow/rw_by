# 🚂 rw_by — расписание поездов Беларуси

Сервис получает расписание поездов с публичной страницы [pass.rw.by](https://pass.rw.by), предоставляет данные через REST API и Telegram-бота, а также умеет периодически отправлять расписание по подпискам.

> Проект не связан с Белорусской железной дорогой. Парсер зависит от текущей HTML-разметки pass.rw.by.

## Текущее состояние

**Реализовано:**
- Асинхронный REST API на FastAPI для поиска поездов по станциям и дате.
- Получение HTML через httpx, повторные попытки при сетевых ошибках, HTTP 429 и 5xx.
- Разбор поездов, времени в пути, дней курсирования, типов вагонов, цен и количества мест.
- Telegram-бот на aiogram 3 с календарём, выбором станции и поиском по названию.
- Просмотр расписания и переход к странице покупки билета.
- Подписки на маршрут и дату с интервалом от 15 минут до 12 часов.
- Периодическая отправка через Celery beat и Celery worker с Redis в качестве брокера.
- Хранение подписок в SQLite, удаление подписок после даты поездки и повторная попытка через 5 минут при недоступности API.

**Пока не реализовано:** автоматизированные тесты парсера, кэширование ответов, рассылка только при изменениях, Docker Compose и постоянное хранилище FSM-состояний.

## Архитектура

| Компонент | Назначение |
|---|---|
| backend/ | FastAPI API, HTTP-клиент для pass.rw.by, парсер и схемы ответа |
| tg_bot/ | Telegram-интерфейс, выбор маршрута, форматирование результатов и управление подписками |
| celery_app/ | Celery-приложение и задача периодической рассылки |

Бот обращается к backend по HTTP и не парсит pass.rw.by самостоятельно. Celery-задача использует HTTP-клиент backend из кода бота, форматтер сообщений и модуль подписок.

## Возможности

### Backend
- GET /trains принимает станции отправления и прибытия, а также дату поездки.
- Один общий httpx.AsyncClient создаётся на время жизни FastAPI-приложения.
- Для сетевых ошибок, HTTP 429 и 5xx предусмотрены до трёх попыток с задержкой и случайным jitter.
- HTML разбирается через BeautifulSoup4, поля поездов извлекаются регулярными выражениями.
- Pydantic-модели задают структуру JSON-ответа; Swagger UI доступен по адресу /docs.

### Telegram-бот
1. Команда /start открывает календарь с выбором даты от текущего дня до 30 дней вперёд.
2. Пользователь выбирает отправление и прибытие: шесть основных станций доступны кнопками, остальные можно найти поиском по названию.
3. Поиск станций не зависит от регистра, считает «е» и «ё» одинаковыми символами и требует минимум два символа.
4. Кнопка **«Показать сейчас»** запрашивает расписание и выводит найденные поезда, время, длительность, дни курсирования, вагоны, цены и места, а также ссылку на pass.rw.by.
5. Кнопка **«Присылать регулярно»** создаёт подписку с выбранным интервалом.
6. Команда /subscriptions показывает подписки пользователя; нажатием на подписку её можно отменить.

Сообщения форматируются в HTML, значения из ответа экранируются. Длинные сообщения делятся на фрагменты размером до 3500 символов.

### Подписки и рассылки
- Подписка уникальна для комбинации чата, станций отправления и прибытия и даты поездки. Повторное создание такой подписки обновляет интервал.
- Подписки хранятся в subscriptions.db в корне проекта.
- Celery beat ставит задачу в очередь каждые 60 секунд. Это частота проверки подписок, а не обязательная частота отправки.
- Celery worker группирует подписки, готовые к отправке в одном цикле, по маршруту и дате, чтобы повторно использовать один ответ backend для группы.
- Между запросами к разным маршрутам worker делает паузу 1–3 секунды.
- Если backend временно недоступен, отправка откладывается на 5 минут.
- Если пользователь заблокировал бота, его подписки удаляются.
- Время следующей отправки хранится в UTC; расписание Celery настроено на Europe/Minsk.

**Ограничение:** сейчас по подписке отправляется полное расписание на каждом цикле, а не только изменения цен или наличия мест. Объединение запросов действует только для подписок, которые готовы к отправке в одном цикле.

## Технологии

- **Язык:** Python 3.10+
- **API:** FastAPI, Uvicorn, Pydantic v2, pydantic-settings
- **Получение и разбор данных:** httpx, BeautifulSoup4, fake-useragent, регулярные выражения
- **Telegram:** aiogram 3, aiogram-calendar, aiohttp
- **Фоновые задачи:** Celery 5, Redis
- **Хранение подписок:** SQLite

## Установка

Требуются Python 3.10+, Git и Redis. Redis можно запустить локально или через Docker:

~~~bash
docker run -d --name rw-by-redis -p 6379:6379 redis:7
~~~

Клонируйте проект и установите зависимости:

~~~bash
git clone https://github.com/AlexeyDemidow/rw_by.git
cd rw_by

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

python -m pip install -r requirements.txt
~~~

## Конфигурация

Создайте файл .env в корне проекта на основе .env.example и заполните значения:

~~~dotenv
BASE=https://pass.rw.by
URL=/ru/route

BOT_TOKEN=your_telegram_bot_token
ADMIN_ID=your_telegram_user_id
BACKEND_URL=http://127.0.0.1:8000

REDIS_URL=redis://localhost:6379/0
~~~

| Переменная | Используется в | Назначение |
|---|---|---|
| BASE | Backend | Базовый адрес pass.rw.by |
| URL | Backend | Путь страницы поиска, обычно /ru/route |
| BOT_TOKEN | Bot, Celery | Токен Telegram-бота от [@BotFather](https://t.me/BotFather) |
| ADMIN_ID | Bot | Telegram ID администратора для уведомлений о запуске и остановке |
| BACKEND_URL | Bot, Celery | Адрес запущенного FastAPI |
| REDIS_URL | Bot settings, Celery | URL брокера Redis |

Каждый компонент загружает только необходимые ему настройки. Для полноценного запуска всех компонентов должны быть заданы все перечисленные переменные.

**Безопасность:** не добавляйте настоящий .env, токен Telegram или локальную базу подписок в Git. Перед публикацией проверьте, что .env, subscriptions.db и файлы celerybeat-schedule* исключены из отслеживания. Если токен уже попал в публичный репозиторий, отзовите его через BotFather и создайте новый.

## Запуск

Запустите Redis, а затем откройте **четыре отдельных терминала** в корне проекта.

### 1. Backend

~~~bash
uvicorn backend.app.main:app --reload --reload-dir backend
~~~

API и интерактивная документация:
- API: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs

### 2. Telegram-бот

~~~bash
python -m tg_bot.bot
~~~

Откройте бота в Telegram и отправьте /start. Для отправки стартового уведомления администратор должен предварительно открыть диалог с ботом и написать ему.

### 3. Celery worker

~~~bash
celery -A celery_app.app worker -l info
~~~

В текущей конфигурации установлен worker_pool="solo", чтобы упростить запуск на Windows.

### 4. Celery beat

~~~bash
celery -A celery_app.app beat -l info
~~~

Запускайте **только один экземпляр Celery beat**: несколько экземпляров могут поставить одинаковые периодические задачи в очередь.

Чтобы вручную запустить задачу рассылки:

~~~bash
celery -A celery_app.app call celery_app.tasks.send_subscriptions
~~~

Задача обработает только подписки, у которых наступило время следующей отправки. Для проверки сначала создайте подписку через бота.

## REST API

### GET /trains

Все параметры обязательные:

| Параметр | Тип | Описание |
|---|---|---|
| dep_station | string | Станция отправления |
| arr_station | string | Станция прибытия |
| trip_date | date, YYYY-MM-DD | Дата поездки |

Пример:

~~~bash
curl "http://127.0.0.1:8000/trains?dep_station=Минск-Пассажирский&arr_station=Гомель&trip_date=2026-10-23"
~~~

Ответ содержит массив trains и order_url. У каждого поезда могут быть номер и тип, станции, время отправления и прибытия, длительность, дни курсирования, метки и список типов вагонов с вариантами цены и количества мест. Цена сериализуется строкой, поскольку в модели используется Decimal.

### Коды ответов

| Код | Значение |
|---|---|
| 200 | Запрос обработан; массив trains может быть пустым |
| 404 | Сайт вернул HTTP 400/404, например из-за некорректной станции |
| 422 | Не прошла валидация параметров FastAPI |
| 502 | Не удалось получить или разобрать ответ pass.rw.by |

## Известные ограничения

- Парсер зависит от HTML-разметки pass.rw.by; изменение сайта может потребовать обновления селекторов и регулярных выражений.
- Список станций хранится непосредственно в tg_bot/keyboards/keyboards.py; callback-кнопки используют индексы отсортированного списка станций.
- FSM-состояния бота хранятся в памяти и теряются при перезапуске. Подписки сохраняются в SQLite.
- Бот пока показывает общее сообщение об ошибке backend, не различая HTTP 404, 422 и 502.
- Автоматизированные тесты, контейнеризация приложения и production-конфигурация пока не добавлены.
